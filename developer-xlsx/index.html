工作台复现案例 · 软件开发场景

手机派任务，原对话取 Excel

假设你离开电脑时只拿到几条回归结果。回程拿出手机，把它们交给自己电脑上的工作台整理成一份 Excel，完成后就在原对话拿原件，不用回电脑找文件。

  • 4 条合成用例
  • 1 次任务 · 1 次成果交付
  • 原文件可直接下载

先拿一份样例，不用安装

这是隔离演练中通过成果卡下载的原始 Excel，含 4 条合成明细。下载 Excel 样例，不需要账号、模型或 Fork。

这次实际走了什么

  1. 在 390 像素宽的手机浏览器模拟里打开独立测试项目「移动登录页」，选择工作区可写，发送四条合成回归结果。
  2. 测试替身在任务收到后生成真正的 .xlsx，由公开版工作台的成果工具交付到对话。点成果卡下载，核对 Excel 中有 4 条明细：通过 2 项、待复测 1 项、阻塞 1 项。
  3. 回项目的对话列表，点回原对话再下载一次。文件名、下载入口和 SHA-256 都相同，不需要重新发送任务。
验证边界：维护者模拟开发人员，不是外部试用。隔离环境使用公开版 preview.4 源码，登录用虚拟 Passkey，执行端用本地测试替身。发任务、成果交付、浏览器下载和历史回开走实际工作台代码；本轮未调用模型、未用实体手机，未验证新电脑安装。表格里的测试结果也是合成数据。

已经装好？复制这段话试一次

在自己的工作台打开一个空测试项目，点项目快捷操作里的「配置后开始」；若是首次设置，选「工作区可写」。复制下方整段并发送。等待对话出现可点的成果卡，下载后打开 Excel；只看到本地路径，不算交付。然后返回项目，重新打开同一条对话再取一次。只体验或安装都不必 Fork。

把 WEB-217 的四条合成结果做成《移动登录页回归台账.xlsx》：
WEB-217-1｜正确账号登录｜通过｜正常进入首页
WEB-217-2｜错误密码提示｜通过｜提示清楚，仍停留在登录页
WEB-217-3｜刷新后维持登录｜待复测｜等移动浏览器环境复测
WEB-217-4｜弱网下重复提交｜阻塞｜合成数据：待弱网环境可用

表头为编号、检查项、状态、说明。加一个“说明”页，注明数据是合成的，并统计各状态。只在这个测试项目生成文件，不改其他项目、不联网。用本对话的交付工具发布生成的 Excel 原件，不要只给本地路径。

还没装可看正式快速开始。实际安装需要 Windows／WSL2、自己的 Codex 访问权限、受信 HTTPS 和保持运行的电脑。公开的免登录演示是静态 CSV 流程，与本次实际下载的 Excel 样例不同。

想改造？先改一处看得见的地方

我模拟了一位开发者的第一个小改动：原来的成果卡只写「下载」，让 Excel 卡明确显示「下载 Excel」。仅改变标签，不碰下载地址、权限或任务执行。

  1. 在自己克隆或 Fork 的干净源码工作区创建实验分支：git switch -c demo/xlsx-label f7bc1a7。
  2. 打开 static/conversation.js，找到 artifactSection() 末尾通用文件卡的 var fileDownload。把原来这一行替换为：
var fileDownload = node('span', 'native-download',
  extension === 'XLSX' ? '下载 Excel' : '下载');

这行保持同一个下载链接，只给 XLSX 分支加提示。可先运行 node --check static/conversation.js。让独立测试实例运行该分支，刷新并打开原测试对话；确认标签变为「下载 Excel」，再下载以核对两个文件一致。仅改 clone 不会自动改到已安装的工作台，不要覆盖日常实例。

本轮可核对的结果
  • 390 / 360 像素宽度验证；原版、重开、改造与恢复原标签共下载 5 次，全部为同一字节内容。
  • 仅 1 次 turn/start、1 次成功交付；下载、重开和标签改动均未再次启动任务。
  • 案例原件：移动登录页回归台账.xlsx，6465 字节。SHA-256：3380743aa4b4ee448c06d69437bb7a1e58043d990fdbbab1b969495206a8dada。

Send from a phone, collect the original Excel file in the same chat

In this maintainer-run case, a mobile-sized browser sent one task to an isolated preview.4 workbench. A local test stub generated a real XLSX from four synthetic test results. The workbench delivered it to the conversation. Reopening the conversation from project history preserved the same download; all five downloads matched byte for byte. No model or physical phone was used.

  • Try on your own Windows/WSL instance with your own Codex access and trusted HTTPS.
