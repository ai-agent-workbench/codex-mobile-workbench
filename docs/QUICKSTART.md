# 从电脑准备到手机首次成功

> 从本项目 [Releases](https://github.com/ai-agent-workbench/codex-mobile-workbench/releases) 取得完整 Windows／WSL 附件包并核对校验值；尚无附件时不要把源码归档当作安装包。维护者已在一个独立实例完成手机核心闭环，不代表你的环境已经准备好，也不代表另一台电脑已验收。

旧公开 CLI／Kimi 工作台不是本项目的原地升级来源。首次使用请建立独立实例，不覆盖旧配置或资料；见 [旧版关系与兼容说明](LEGACY_COMPATIBILITY.md)。

## 1. 准备环境

首版目标：Windows、Ubuntu 24.04 WSL2、x86-64、Python 3.12（含 venv／ensurepip）、Git、curl、可用的 systemd 用户服务，以及可访问上游的软件下载网络。需要一台支持 WebAuthn／Passkey 和受信 HTTPS 的真实手机。

面板不会自动安装 WSL、sudo 安装系统依赖或提供网络代理。先把环境准备好；[安装原始说明](../INSTALL.md)保留更详细的部署契约。

## 2. 选对下载内容，完整解压

推荐使用 Release 附件里的完整包，内含 `CodexWorkbenchPanel.exe`、源码和 `package-source.json`。GitHub 自动生成的 **Source code (zip/tar.gz)** 只有源码，不含面板和清单，不能直接执行下面的双击安装步骤。

自行构建时，请用 Git 获取已选定的固定版本，按 [Windows 面板构建说明](../desktop/README.md) 编译面板，再在 WSL 用 `scripts/build-desktop-package.py` 生成完整同包目录。不要从未知位置下载一个 EXE 拼进源码，或手写清单绕过校验。

## 3. 检查新实例

1. 完整解压同包目录；面板 EXE、源码和 `package-source.json` 不要拆开。
2. 双击 `CodexWorkbenchPanel.exe`，选择自己的 Ubuntu 发行版，点“运行检查”。未签名程序若被系统策略阻止，停止并核对来源／组织策略，勿绕过保护。
3. 在该 WSL 的本人主目录下选择新的独立目录。不要填写现有工作台目录，不覆盖已有数据。
4. 点“安装准备”并核对范围。选择“沿用现有 WSL 配置”（默认）、“明确直连”或“指定 HTTP(S) 代理”，保存设置后再点“安装”。不要求所有人安装代理；沿用模式读取 WSL 进程代理变量，不自动读取 Windows 系统代理。安装会创建独立软件／状态／workspace／原生 HOME 和用户服务；下载固定原生程序、按锁定版本安装 Python 依赖。未完成时不要把检查页当成已安装成功。

如果已有可用代理，优先沿用，不自动替换；若需要指定地址，在面板内填写，不改源码。指定代理失败会停在该下载阶段，不偷偷直连；国内依赖下载成功也不等于账号登录或模型服务可用。完整优先级、`NO_PROXY` 与私有保存规则见 [联网说明](../INSTALL.md#联网方式)。

## 4. 本人登录，准备手机入口

5. 点“原生账号登录”，由本人在打开的原生终端和浏览器完成登录。设备码、Token、登录画面不发给维护者。
6. 再运行检查。账号登录、服务就绪、模型调用成功是不同事实，检查通过不等于已经产生过真实模型轮次。
7. 先按 [手机接入路线](PHONE_ACCESS.md) 比较私有组网和托管 HTTPS，再使用自己的受信 HTTPS 入口，将新实例的回环端口接成**独立入口**；保留 WebSocket，禁止对外转发 `/internal/`，不暴露原生 socket。不要借用作者域名或接管现有服务。
8. 在面板保存自己的 HTTPS 来源。**保存 URL 只记录配置，不自动接通网络。** 先确认手机能打开正确实例的登录页。

## 5. 手机绑定和首次任务

9. 启动该实例，用手机扫描普通访问二维码。再点击电脑面板“绑定手机”，在手机完成短期一次性授权和本人设备验证。不要截图分享绑定口令。
10. 在新建的演示项目／workspace 中上传自己可公开的合成资料，先核对新对话的模型和权限，再发起一个小任务。
11. 打开并下载成果，确认文件内容与项目归属。锁屏／切后台后返回，再进行一次网络断开／恢复，确认还是原任务而不是重复执行。
12. 记录结果与不通过的具体步骤，勿发送完整私有日志或资料。此前没有通过的地方需要修复后再验，不直接进入对外试用。

首次准备时间取决于已有 WSL、软件下载网络和 HTTPS 条件。扫码只解决访问／绑定中的一步，不等于从零部署；先逐项完成前置条件，再验证任务和成果。

## 可选项与退出

新实例定时任务和完成通知默认关闭；需要时在电脑面板部署设置中启用。未配置通知时不影响核心对话，不应收到测试通知。退出面板不会停止后台服务；停止、备份和卸载见 [维护说明](OPERATIONS.md)。
