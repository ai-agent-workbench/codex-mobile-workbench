# v0.1.0-preview.4 · 恢复范围可见与隔离故障演练

## 本次变化

- 备份与恢复返回结构化摘要：包含／排除范围、敏感资料提醒、校验状态、UTC 时间和下一步；桌面面板在操作前预检、完成后显示可滚动的完整结果，并可重新打开。状态刷新失败不会抹掉已完成结果。
- 新备份记录 v2 时间字段；已有 v1 恢复点继续可读，缺失时间明确显示未知，不猜测历史时间。恢复仍到新目录，不覆盖源实例、不迁移登录、不自动启用服务或重放命令。
- 摘要复用已通过校验的数据，不在成功恢复后再次扫描源恢复点。源恢复点在最终检查后移动，也不会把已经有效的目标误标为恢复失败。
- 公开 CI 新增同一隔离实例的连续演练：真实 HTTPS／WebAuthn、生产对话页面与运行时、浏览器离线／冻结返回、同根 Web 进程重启、备份后恢复到新根、旧会话拒绝、重新认证、前后文件 SHA-256 一致及未决命令不重发。

## 证据与边界

演练使用合成数据及只实现所需 RPC 的本地 UDS 对端，不调用真实模型；不是实体手机后台行为、WSL 整机重启、生产网关或另一台电脑的验收。没有因为演练而扩大备份到外部工程／原生凭据。对应提交的公开检查结果以 [Actions](https://github.com/ai-agent-workbench/codex-mobile-workbench/actions) 为准。

完整包为 `Codex-Mobile-Workbench_Windows-WSL_v0.1.0-preview.4.zip`，核对同页 `SHA256SUMS.txt`。保留旧发行与附件，不自动更新现有安装。Windows 面板仍未签名，支持平台、首次权限选择与安装依赖条件沿用 preview.3；详见 [支持矩阵](SUPPORT_MATRIX.md) 与 [恢复操作](OPERATIONS.md)。

# v0.1.0-preview.3 · 首次权限自选与公开质量检查

保留完全访问能力，让新用户先明确选择，再开始任务；同时让源码、依赖和发行包更容易核验。

## 本次变化

- 新安装实例的每个账号，首次新建对话前明确选择只读、工作区可写（推荐）或完全访问。三个选项均不预选；一次保存决定之后新对话的账号默认值，可继续在设置中调整。
- 已有 v1 实例不被当成新用户：即使从未保存设置，也保留原默认行为。已有对话不被改权，项目覆盖仍按既有规则生效。不增加命令白名单或日常重复确认。
- 选择结果与完成标识原子保存，支持冲突后保留选择重试；恢复到新目录继承备份的 v1/v2 语义及已保存选择，不因为目录是新的就重置权限。新 v2 profile 不兼容不认识该格式的旧控制器，不能向其回退。
- 核心及传递运行依赖加入 wheel 内容 SHA-256，安装强制核验且不静默降级。更新实际审计发现的漏洞依赖，并补齐可选锁的依赖闭包。支持平台和维护流程见 [Dependency content locks](DEPENDENCIES.md)。
- 增加公开 GitHub Actions：Python 全量、离线手机 UI、Windows 面板构建／自测、同次运行的安装包校验、五组依赖漏洞检查。使用只读仓库权限和固定 Action SHA；不读取私密凭据、不调用付费模型、不自动发布。

## 下载与边界

完整包为 `Codex-Mobile-Workbench_Windows-WSL_v0.1.0-preview.3.zip`，请核对同页 `SHA256SUMS.txt`。包内包括源码、Windows 面板和源码清单；GitHub 自动 Source code ZIP 不替代完整包。保留旧版本及原附件，不自动更新已安装实例。

仍是 Windows＋Ubuntu 24.04 WSL2、x86-64、Python 3.12 的技术预览，固定 Codex 0.160.0。Full Access 可能访问工作区外的可访问文件、执行命令和联网，上限是运行账号的系统权限，并不等于管理员。Windows 面板仍未签名；哈希和 CI 不是代码签名、安全保证或可复现构建证明。

本轮工程回归、离线 UI、依赖与发行包检查，与历史实体手机验收分别记录。当前远程检查以对应提交的 [Actions](https://github.com/ai-agent-workbench/codex-mobile-workbench/actions) 结果为准。没有另一台电脑的新一轮验收，也不把合成测试说成真实模型任务；完整范围见 [支持矩阵](SUPPORT_MATRIX.md)。

# v0.1.0-preview.2 · 更容易装好、连上、完成第一个任务

任务在自己的电脑上执行，手机继续操作、取得成果。本次小修复优先降低安装联网门槛，不增加新的业务功能。

## 本次修复

- 安装不再一律要求代理；本实例可选择沿用现有 WSL 配置、明确直连或指定 HTTP(S) 代理。
- 下载、原生登录与后台服务共用已保存的网络策略；保留 NO_PROXY／本机例外，失败不静默换路。检查不回显代理地址或认证信息。
- 依赖下载与原生程序下载分别报错；模型真实连接、手机当前可达明确保持待验证，不用本地登录或已保存地址冒充。
- 修复实例目录含单引号等字符时 systemd 拒绝原生启动路径的问题；使用无 shell 的绝对路径 exec，并增加真实单元语法验证。
- 补清 WSL 的历史选择原因、Windows 原生面板与原生后端边界，以及私有组网／托管 HTTPS 的接入对比。
- 保留 v0.1.0-preview.1 的源码、版本和附件；下载新版不会自动更新已有实例，不改变账号、网关或手机绑定规则。

## 下载与验证范围

选择本版 Release 的 `Codex-Mobile-Workbench_Windows-WSL_v0.1.0-preview.2.zip`，并核对同页 `SHA256SUMS.txt`。完整包包含源码、未签名 Windows 面板和安装清单；不包含原生 Codex 程序、Python wheels、模型、账号或用户资料，安装仍需联网取得固定上游依赖。GitHub 自动生成的 Source code ZIP 不是完整安装包。

本版仍是 **Windows 面板＋WSL 后端的技术预览**，不是 Windows 原生后端或从零一键部署器；新实例按 `docs/QUICKSTART.md` 创建。

- 受检实现通过 1424 项回归；同一宿主中新建含中文、空格、括号、单引号的独立目录，用完整成品包完成实际安装、清单核验及保留资料卸载。

# v0.1.0-preview.1 · 电脑执行，手机掌控

我不会写代码，但我和 AI 一起，把自己的需求做成了一个真实能用的工作台。现在，把这条路径整理成新一代开源项目：**Codex Mobile Workbench**。

有想法，用手机派任务；需要调整，继续追问；做出文件，直接查看和下载。电脑负责执行，手机负责指挥。

## 这次带来了什么

- 原生 Codex App Server 的项目／对话／任务交互链，不再沿用旧 CLI／Kimi 架构。
- 手机上传资料、跟进任务、处理原生交互，以及受本人认证保护的文件成果入口。
- Windows 原生薄面板和 WSL 独立实例：检查、安装、本人登录、手机接线、启停、备份及新目录恢复。
- 固定 0.160.0 完整原生运行包与成员校验，保留官方布局、资源和法律文本；不只检查单个 CLI 版本。
- 明确的文件交付成功／失败回执，以及独立于成果交付的标题保护提示。

目标环境是 Windows＋Ubuntu 24.04 WSL2、x86-64、Python 3.12。使用自己的电脑、Codex 账号和手机可达的可信 HTTPS；电脑需要保持运行。按仓库中的 `docs/QUICKSTART.md` 新建独立实例，不覆盖旧工作台。
