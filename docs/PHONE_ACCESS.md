# 手机网址：没有现成地址时，先看这里

任务在自己的电脑上执行，手机继续操作、取得成果。要让手机找到这台电脑，需要一个属于你自己的、稳定且受信的 HTTPS 网址。

**安装本软件不会自动给你创建这个网址。** 面板里的“手机 HTTPS 入口”是填写已经准备好的地址，不是申请网址的按钮；二维码也只是显示这个地址，不会替你接通网络。

当前仍是技术预览：下面说明网址从哪里来、应按什么顺序准备，以及候选方案的验证边界。**尚未完成普通家庭网络下可直接推荐的默认路线实测**，不能把这页当作“一条命令即可接通”的保证。

## 1. 先分清三个东西

| 你看到的内容 | 它是什么 | 怎么用 |
|---|---|---|
| 面板显示的 `http://127.0.0.1:端口` | 电脑上的本机服务地址 | 提供给连接工具作为转发目标；手机上的 `127.0.0.1` 指手机自己，不是这台电脑 |
| 自己的稳定 `https://…` 地址 | 手机真正使用的访问网址 | 由你选择的组网／托管服务提供，或由你已有的可信入口配置而来，再填回工作台面板 |
| “绑定手机”显示的一次性口令 | 本人设备的短期授权 | 只在自己的手机绑定页面使用，不是网址，不要截图分享 |

如果你已经有自己的稳定 HTTPS 入口，可继续下面的准备顺序。如果你只有本机地址，或完全没有网址，先选择下一节的路线。

网址不能凭空填写。`example.invalid` 只是示例，不是可用服务；作者的地址、别人的网址和临时绑定链接也不能作为你的入口。面板只填来源地址，不带 `/login`、查询参数或绑定口令。

## 2. 没有网址，可以从哪里取得？

普通家庭宽带不一定有可入站的公网地址，但这不等于必须购买服务器、购买域名或开放路由器端口。可先比较两类路线：

| 路线 | 手机需要做什么 | 网址怎样取得 | 选择前确认 |
|---|---|---|---|
| 私有组网＋可信 HTTPS | 通常需安装组网客户端，并把自己的电脑和手机加入本人网络 | 使用支持自动 HTTPS 的组网服务，为电脑的本地服务取得该服务分配的稳定 HTTPS 地址；不一定要自己买域名 | 是否支持你的电脑和手机、HTTPS 是否需本人开启、哪些设备能访问、账号与套餐限制 |
| 托管 HTTPS 入口 | 通常只用浏览器 | 电脑运行所选服务的连接器，按其流程取得或绑定固定地址，再把该地址指向本实例 | 是否需要自己的域名、地址是否长期固定、是否公开可访问、第三方可见哪些数据、费用与稳定性 |

这两类路线不是“先随便填一个网址，再想办法让它能用”。应先在所选服务中准备好你有权使用的稳定地址，再把它保存到工作台。

私有组网的最小准备顺序是：双端安装并登录组网服务的本人账号 → 确认设备与访问规则 → 按服务要求开启 HTTPS → 从服务界面或命令结果取得真实网址。组网服务登录与 Codex 原生账号登录是两件事。**私有组网不等于公网公开访问**，不要为了省一步而改成公开模式。

托管入口的最小准备顺序是：确认账号、固定地址及费用条件 → 配置电脑连接器和访问范围 → 按下一节的网关要求接到本实例端口 → 取得真实网址。不同服务可能分配地址，也可能要求自备域名，不能一概承诺免费或免域名。

这些是准备路径，不是已经实测通过的具体服务操作配方。先看第5节的已知证据；遇到必须新增账号、公开入口或改变访问范围的步骤，应由实例所有者明确选择，不替换已有组网或日常服务。

## 3. 正确顺序：先知道端口和网址，再启动验证

1. 完成独立安装和本人原生账号登录，点“运行检查”，记录面板显示的本机端口。**不用先启动服务才知道这个端口。**
2. 选择入口路线，准备属于自己的稳定 HTTPS 地址，并让入口指向本实例的本机端口。此时后端尚未启动，不能用手机页面是否打开来判定最终连通。
3. 配置入口时保留 WebSocket、正确 Host／HTTPS 来源信息；**不得转发 `/internal` 及其子路径，不得暴露原生 App Server 或 socket**。自动提供 HTTPS 只解决了一部分问题，不代表这些隔离要求已自动完成。
4. 将准备好的 HTTPS 来源保存到工作台面板，再点“启动”。启动要求已保存来源且已完成本人原生登录；安装本身不会自动启动。
5. 启动核验通过后，用手机扫描普通访问二维码，或直接打开保存的网址，确认是正确实例的登录页、没有证书警告。用你实际打算使用的手机网络验证；打算外出使用时，再确认蜂窝网络也能打开。
6. 再点电脑面板“绑定手机”，完成自己的短期授权／Passkey 绑定；随后按 [快速开始](QUICKSTART.md) 发送合成小任务并取得文件。

如果不知道怎样满足第3步，不要把全部电脑端口直接开放，也不要跳过证书或登录保护。当前候选还需把这些要求验证成可照做的具体配置，不能把一条简单转发命令当作完整安全接入方案。

使用稳定、可信的独立 HTTPS hostname；同一 hostname 换路径或端口不能假装 Cookie 隔离。Passkey 绑定依赖来源，临时随机域名变化可能导致无法按原方式登录；已有绑定不能靠随意改 URL 自动迁移。私有网络不代替本人认证，HTTPS 也不等于访问控制；工作台不是多人公共服务。

## 4. 卡住时先分清是哪一段

| 现象 | 优先核对 | 不要先做 |
|---|---|---|
| 没有自己的 HTTPS 网址，不知道填什么 | 第2节的账号、固定地址和入口准备条件 | 随便填写示例网址或作者地址 |
| 手机打不开页面 | 本实例是否已启动、入口／连接器是否在线、手机是否已加入所选私有网络 | 反复重新登录 Codex，把网址问题当模型问题 |
| 有证书警告或进了其他网站 | 真实网址、证书和配置的实例是否一致 | 跳过证书保护继续绑定 |
| 登录页能打开，但绑定或任务失败 | 手机本人认证、原生登录与模型连接分别核对 | 把“页面能开”当全部成功，或重复发送状态不明的任务 |

## 5. 目前核实了什么，仍缺什么？

2026-10-28 经既有受控代理核对了以下官方资料；它们证明服务具备相应能力，**不等于本项目已经完成这些第三方路线的真实手机验收**。

- [Tailscale Serve](https://tailscale.com/kb/1312/serve)：可在本人的 tailnet 内，将本地服务转为该设备的 HTTPS 地址，所用域名来自该服务的设备／网络域名。需要本人按流程开启 HTTPS。[HTTPS 官方说明](https://tailscale.com/kb/1153/enabling-https)提示证书透明记录会公开证书中的设备域名，不能使用敏感设备命名。**Serve 与公开 Funnel 不同**，不能静默启用 Funnel。尚未将其与本项目的内部路径隔离、本人绑定和真实手机任务一起验证。
- [Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/)：连接器主动连出，可将固定 hostname 接到本机服务；无需以开放家庭公网入站为前提，仍须核对自己的账号、域名、TLS 和费用。[入口规则官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/configuration-file/)提供路径匹配／拒绝响应配置，但不能把未按对应版本实际核验的规则当作安全边界。尚未为本项目候选创建或验证真实托管入口。
- [Quick Tunnels](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)属于测试／开发用途、使用临时地址，不能因无需账号就作为长期绑定的默认方案。当前浏览器更新使用 WebSocket，仍需验证实际隧道，不能从协议名称推导稳定可用。

经维护者代理读到官方网页，不证明普通家庭网络可直连服务；本机 TLS／代理隔离测试也不代替第三方接入实测。**手机网址的完整上手方案仍是未完成项**：至少需有一条在普通家庭网络可用、稳定网址可取得、内部路径不外露、本人绑定及任务／文件取得都通过的路线，才能作为默认推荐；目前不选默认服务商。

首次使用与路线可靠性也要分开：本人手机能发任务、取得并核对文件，是首次成功；锁屏／切后台、切网／断网恢复、停用／恢复连接器等，是后续按需验证。维护者要据这些额外证据评估推荐范围，而不是要求每个新用户先替项目跑完整套测试。
