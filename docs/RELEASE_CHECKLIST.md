# 发行核对清单

这是一份维护者使用的发行流程，不是要求使用者重复完成本项目的全部工程验收。公开源码、附件和旧仓指路须符合当前明确的发布决定；技术准备不自动代替项目介绍定稿。

## 内容和权利

- 固定干净的公开源码快照；只推送受检分支，不带私有提交历史、运行状态、认证资料、生产配置或不可达 Git 对象。
- 保留 MIT 和既定公开版权署名，第三方 LICENSE／NOTICE、协议材料来源及图标生成记录独立保留。
- 检查源码和提交元数据的隐私；使用中性名称与 GitHub noreply 身份，不把示例值误报为真实秘密。
- 新旧仓库关系、已支持能力和不兼容变化明确；不承诺未经验证的旧公开版原地升级／数据导入。
- 首页、仓库简介和发布介绍按所有者确认的表达定稿；演示只使用合成或明确可公开的资料，不冒充真实实机证据。

## 行为和支持边界

- 改动后的相关回归和必要独立检查通过；只在代码、环境和检查前提仍适用时复用已有结果，不靠跳过失败放行。
- 本次已有原生登录、独立 HTTPS、实体手机绑定、真实任务和成果下载内容确认；不把它扩大为另一台电脑、原生 Linux、完整切后台／断网或旧公开版导入已验收。
- 新实例独立安装，默认回环监听，外部 HTTPS 由所有者准备；原生权限、本人认证、费用和数据恢复范围各自说明。
- GitHub 私密漏洞报告实际启用并核对，SECURITY 和问题模板指向真实入口；不虚构邮箱、响应时限或安全保证。

## 制品和公开核验

- 从固定干净 Git 版本生成完整 Windows／WSL 包，包括源码、实际构建的面板和 package-source.json；GitHub 自动源码归档不能冒称完整安装包。
- ZIP 路径、成员类型、大小、SHA-256、源码清单与面板校验一致；不含原生二进制、wheels、凭据或用户资料。未签名 EXE 不要求绕过系统保护。
- 版本标为技术预览，公开后核对主分支／tag 的精确提交、附件下载字节和校验值，确认匿名可访问。
- 旧仓只增加新项目指路，保留旧代码、版权和提交历史，不删除／强推改写；使用预期旧文件 SHA 防止覆盖并发改动。
- 记录真实成功、失败和未覆盖项。只有工具或 GitHub 返回并经状态核对成功后，才声称已经发布；不确定投递不自动重做。

外部试用者招募、宣传、长期维护承诺、通知／定时任务和操作系统迁移不是创建公开仓库的自动附带动作，应按实际授权另行决定。
